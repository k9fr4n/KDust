# Docker MCP Gateway — operator handbook

Status: **Accepted (ADR-0012, V2 with UI)**. Companion document
to the ADR in `README.md`.

> Since 2026-05-10 the recommended way to declare servers /
> bindings / project filters is the **`/settings/mcp` UI**. The
> `scripts/seed-mcp-gateway.mjs` script is kept as a fallback for
> bootstrap or scripted installs but the UI is now the source of
> truth. The "Apply changes" button there rewrites
> `/mcp-gateway/secrets/kdust-mcp.env` and restarts the gateway
> container in one click (DooD `docker restart kdust-mcp-gateway`).

This page covers the practical side of running the Docker MCP
Gateway alongside KDust: docker-compose snippet, adding /
removing a catalog server, secret management, per-project tool
whitelisting, and debugging recipes.

## What it is

A single long-lived container (`docker/mcp-gateway`) sits on the
Compose-internal network and multiplexes N MCP servers from the
Docker Hub catalog (`hub.docker.com/mcp`). It speaks streamable
HTTP MCP on `:8080/mcp`. KDust opens **one** MCP `Client`
connection at boot, lists the available tools, and re-exports
them to Dust per-project via `DustMcpServerTransport`-backed
proxies.

Key properties:

- **No public ingress.** `expose: 8080` only — reachable only
  from sibling Compose services.
- **Auth disabled** on the internal network thanks to
  `DOCKER_MCP_IN_CONTAINER=1`.
- **DooD**: the gateway needs `/var/run/docker.sock` to spawn the
  child MCP containers it multiplexes.
- **Default-deny** per-project: a project sees zero tools until
  an operator whitelists them in `/settings/mcp`.

## docker-compose snippet

Added service (next to `kdust` and `watchtower`):

```yaml
  mcp-gateway:
    image: docker/mcp-gateway:latest
    container_name: kdust-mcp-gateway
    restart: unless-stopped
    pull_policy: always
    labels:
      - "com.centurylinklabs.watchtower.enable=true"
      - "com.centurylinklabs.watchtower.scope=kdust-autoupdate"
    environment:
      - DOCKER_MCP_IN_CONTAINER=1
    command:
      - --transport=streaming
      - --port=8080
      - --servers=github-official
      - --secrets=/secrets/kdust-mcp.env
      - --block-secrets
      - --verify-signatures
      - --log-calls
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - ./mcp-gateway/secrets:/secrets:ro
    expose:
      - "8080"
    mem_limit: 1g
    cpus: 2.0
```

And on the existing `kdust` service:

```yaml
    volumes:
      # ... existing entries ...
      - ./mcp-gateway/secrets:/mcp-gateway/secrets   # rw, KDust writes the env file
    environment:
      - MCP_GATEWAY_URL=http://mcp-gateway:8080/mcp
      - MCP_GATEWAY_SECRETS_DIR=/mcp-gateway/secrets
    depends_on:
      - mcp-gateway
```

Directory layout on the host (next to `data/` and `projects/`):

```
/home/kfr/docker/KDust/
  docker-compose.yml
  data/
  projects/
  mcp-gateway/
    secrets/      # 0700, owned by uid 1000 (node)
      kdust-mcp.env  # 0600, generated by KDust at boot + on Secret edits
```

## Adding a server

1. Find the server slug on `https://hub.docker.com/mcp` (e.g.
   `context7`, `mcp-discord`, `brave-search`).
2. Note its required secrets — listed under the **Config** tab
   on the server page.
3. Create the corresponding `Secret` rows in KDust
   (`/settings/secrets`) and bind them to the server. The binding
   stores the **catalog secret key** (e.g.
   `github.personal_access_token`), not the POSIX env var. The
   gateway maps the catalog key to the underlying image's env var
   itself.

   V1 (2026-05-10) ships **without** a `/settings/mcp` UI. Use
   `scripts/seed-mcp-gateway.mjs` (edit the `SEED_DATA` constant,
   then `docker exec -it kdust node scripts/seed-mcp-gateway.mjs`)
   to populate `McpGatewayServer`, `McpServerSecret`, and
   `ProjectMcpToolFilter`. The CRUD UI is deferred to a follow-up
   ADR.
4. Edit `docker-compose.yml`: append the slug to `--servers=`.
5. `docker compose up -d mcp-gateway` (KDust does not need to
   restart — its `Client` reconnects automatically and re-runs
   `tools/list`).
6. Whitelist the new tools per project in `/settings/mcp`.

## Removing a server

1. Remove the slug from `--servers=` in `docker-compose.yml`.
2. `docker compose up -d mcp-gateway`.
3. Optional: drop the matching `Secret` rows if they were
   server-specific.

KDust's `Client` will see the tool disappear on the next
`tools/list`; project filters referencing the removed tool become
inert (no error).

## Secret management

- Each catalog server declares the env vars it consumes (cf.
  Hub config tab). KDust resolves the bound `Secret` rows, writes
  `mcp-gateway/secrets/kdust-mcp.env` (mode `0600`), and the
  gateway picks them up via `--secrets=/secrets/kdust-mcp.env`.
- Rotation: edit the `Secret` in `/settings/secrets`; KDust
  rewrites the env file, then triggers a gateway restart via the
  Docker socket (DooD `restart kdust-mcp-gateway`).
- The env file is **never** committed and **never** rendered in
  KDust logs — `src/lib/secrets/redact.ts` is applied to all
  proxy stdout/stderr before they reach the log buffer or Teams
  reports.

## Per-project tool filter

New Prisma model `ProjectMcpToolFilter` keyed by project FS path,
with an `allowed` JSON array of `"server.tool"` strings.
Default-deny: empty array → no exposure.

UI: `/settings/mcp` lists the live tools returned by the gateway,
with a checkbox grid `[project] × [tool]`. Saving the row writes
the filter atomically.

The filter is **applied in KDust**, not in the gateway: when a
chat or run requests its proxy `McpServer`, only whitelisted
tools are `registerTool`'d on the Dust transport.

## V1 server: `github-official`

- Slug: `github-official`
- Image (resolved by gateway): `ghcr.io/github/github-mcp-server`
- Required secret: catalog key `github.personal_access_token`.
  Provide a classic PAT or a fine-grained PAT with at least
  `repo:read` for read-only; add `repo:write`, `workflow`, etc.
  as the use case demands.
- 40 tools: issues, PRs, branches, files, releases, search,
  commits, comments. Read-only sub-tools are flagged with
  *"This tool is read-only"* in their description and surface
  that hint to operators in `/settings/mcp`.

Known limits:

- No GitHub Apps / OAuth flow in V1 — PAT only.
- Pushing to a repo via `push_files` bypasses the KDust push
  pipeline entirely (no Teams report, no auto-PR formatting).
  Prefer the push pipeline for repos you also operate from
  Tasks; reserve `push_files` for one-off automations.

## Excluded from V1

The catalog server **`docker`** is intentionally not enabled.
It exposes a single `docker(args: string[])` tool that is an
unbounded shell on the host docker socket and would let any
agent read `kdust` env vars (including `APP_ENCRYPTION_KEY`),
dump `data/kdust.db`, exec into sibling containers, or destroy
the stack. A future ADR will introduce a KDust-managed Docker
introspection tool with a hard-coded sub-command whitelist
(`ps`, `logs`, `inspect`, `stats`) instead.

## Debugging

```bash
# Is the gateway up?
docker compose ps mcp-gateway
docker compose logs --tail=200 mcp-gateway

# What tools does it expose?
docker compose exec mcp-gateway wget -qO- http://localhost:8080/health || true
# (or open a Node REPL inside kdust and call gatewayProxy.listTools())

# Is KDust talking to it?
docker compose logs kdust 2>&1 | grep -i mcp-gateway

# Did a Secret edit propagate?
docker compose exec kdust ls -l /mcp-gateway/secrets/kdust-mcp.env
docker compose exec mcp-gateway env | grep -i ^GITHUB || true   # should be empty (gateway loads via --secrets)
```

Common failure modes:

- **`tools/list` returns empty** → check `--servers=` is set and
  the slug exists in the default catalog
  (`docker compose exec mcp-gateway docker mcp catalog show`).
- **Tool call returns auth error** → secret missing or expired in
  `Secret`; verify `kdust-mcp.env` content (over `cat`,
  redacted server-side).
- **Gateway restarts in a loop** → bad image signature
  (`--verify-signatures`); pin a known tag instead of `:latest`
  while debugging.
